# Зачем?

Скрипт превращает любое приложение в децентрализованное, сохраняя лог и делясь им с другими.

## Запуск

Установка:

```bash
npm install
```

Старт ноды (порт из `API_PORT`, по умолчанию 80):

```bash
npm start
```

Добавить запись:

```bash
curl -X POST http://127.0.0.1/append -H 'Content-Type: application/json' -d '{"msg":"hello"}'
```

Посмотреть состояние:

```bash
curl -X POST http://127.0.0.1/debug
```

## Три ноды в Docker: центр + два воркера

```bash
docker compose up -d
```

Поднимает `node1` (центральный, `13200`), `node2` (`13301`) и `node3` (`13302`). Центральная нода принимает журналы воркеров и редиректит их в свой `/append`, воркеры тянут журнал центра. Данные каждой ноды — в `./node1`, `./node2`, `./node3`.

Ключи нод известны только после старта, поэтому compose правится в три шага.

**1. Поднять центр.** Он назначает себе комнату = собственный локальный ключ:

```bash
docker compose up -d node1
curl -s http://127.0.0.1:13200/debug
```

**2. Прописать этот ключ как комнату (`P2P_ROOM`) в compose и поднять воркеров:**

```yaml
- P2P_ROOM=6b1f5196123339da7a1018f395e140d72493000158cca5c8cc19952d8ac1119d
```

```bash
docker compose up -d node2 node3
curl -s http://127.0.0.1:13301/debug
curl -s http://127.0.0.1:13302/debug
```

**3. Прописать ключи журналов:** центру — список ключей воркеров через запятую, воркерам — ключ центрального журнала:

```yaml
# node1
- P2P_REMOTE_KEY=38e09fb492e0b3154a6724bc6932db27554aa5b3b9f674e5cefaf1731c2b8ec9,0c385e9b2a9e3d371f8dcc8d5cb087625a9ed3e88c7e7b5d19f20e616af1ca96
# node2 и node3
- P2P_REMOTE_KEY=6b1f5196123339da7a1018f395e140d72493000158cca5c8cc19952d8ac1119d
```

```bash
docker compose up -d --force-recreate
```

Проверка:

```bash
curl -X POST http://127.0.0.1:13301/append -d '{"msg":"hello from w1"}'
curl -X POST http://127.0.0.1:13302/append -d '{"msg":"hello from w2"}'
curl http://127.0.0.1:13200/debug   # local_length центра вырос, remotes покажут pos по обоим журналам
```

## Настройки

`config.json` загружается при старте поверх дефолтов, переменные окружения перекрывают файл. 

| Ключ | Дефолт                  | Назначение |
|---|-------------------------|---|
| `API_PORT` | `80`                    | HTTP-порт (`/append`, `/debug`) |
| `P2P_SEED` | строка                  | Определяет `primaryKey` Corestore, то есть личность ноды. Задайте свой, чтобы сохранить её между рестартами |
| `P2P_LOCAL_KEY` | —                       | Ключ собственного журнала, заполняется автоматически |
| `P2P_ROOM` | `''`                    | Идентификатор комнаты (топик Hyperswarm, 32 байта hex). Если не задан — берётся **собственный локальный ключ ноды** |
| `P2P_REMOTE_KEY` | `''`                    | Список ключей чужих журналов через запятую — их нода тянет и редиректит на `P2P_REDIRECT` |
| `P2P_PORT` | `59737`                 | UDP-порт Hyperswarm |
| `P2P_REDIRECT` | `http://localhost:8999` | Адрес, куда уходят записи из чужого журнала |

Позиция указателя по каждому чужому журналу хранится отдельно в `level` (`remote_pos_<ключ>`), в `config.json` она больше не лежит.

### Комната

Комната — это топик Hyperswarm: ноды с одинаковым идентификатором комнаты находят друг друга и обмениваются журналами.

- Если `P2P_ROOM` не задан, нода использует **свой локальный ключ** (`P2P_LOCAL_KEY`) — то есть каждая нода по умолчанию владеет своей комнатой.
- Остальные ноды получают идентификатор комнаты из `/debug` владельца и прописывают его в `P2P_ROOM` — после этого они находят владельца и подключаются к нему.

### Список узлов

`P2P_REMOTE_KEY` принимает несколько ключей через запятую — инициализируются все:

```bash
P2P_REMOTE_KEY=6b1f5196...1119d,a13c77b0...42e,f00dcafe...0011
```

Это журналы, которые нода подтягивает и редиректит на `P2P_REDIRECT`. Указатель по каждому такому журналу свой, записи с уже известным `stamp` повторно не редиректятся.

## Эндпоинты

**`POST /append`** — добавляет запись. Повторный `stamp` игнорируется (запись уже есть).

**`GET` или `POST /debug`** — информация по логу:

| Поле | Значение |
|---|---|
| `room` | Идентификатор комнаты (`P2P_ROOM` либо свой локальный ключ) |
| `local_length` / `remote_length` | Размеры своего и первого чужого журнала |
| `remotes` | Список чужих журналов: `key`, `length`, `pos` (текущая позиция указателя) |
| `local_last` | Последняя редиректнутая запись |
| `swarm_pubkey`, `swarm_peers` | Свой ключ и список подключённых пиров |
| `logs` | Последние 10 строк лога |
