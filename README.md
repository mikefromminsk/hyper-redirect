# hyper-redirect

Любое приложение превращается в децентрализованное: записи пишутся в журнал и расходятся по P2P.

## Быстрый старт

```bash
npm install
npm start
```

```bash
curl -X POST http://127.0.0.1/append -d '{"msg":"hello"}'
curl http://127.0.0.1/debug
```

## Три ноды: центр и два воркера

`docker compose up -d` поднимает:

| нода | порт | роль |
|---|---|---|
| `node1` | `13200` | центр: тянет журналы воркеров и редиректит их в свой `/append` |
| `node2` | `13301` | воркер |
| `node3` | `13302` | воркер |

Данные каждой ноды лежат в `./node1`, `./node2`, `./node3`.

Ключи нод известны только после старта, поэтому compose правится в три шага.

### 1. Центр

```bash
docker compose up -d node1
curl http://127.0.0.1:13200/debug
```

Комната центра — его собственный локальный ключ.

### 2. Воркеры

Впишите ключ центра в `P2P_ROOM` у `node2` и `node3`:

```yaml
- P2P_ROOM=<ключ центра>
```

```bash
docker compose up -d node2 node3
curl http://127.0.0.1:13301/debug
curl http://127.0.0.1:13302/debug
```

### 3. Списки журналов

Центру — ключи воркеров через запятую, воркерам — ключ центрального журнала:

```yaml
# node1
- P2P_REMOTE_KEY=<ключ node2>,<ключ node3>

# node2 и node3
- P2P_REMOTE_KEY=<ключ центра>
```

```bash
docker compose up -d --force-recreate
```

### Проверка

```bash
curl -X POST http://127.0.0.1:13301/append -d '{"msg":"hello from w1"}'
curl -X POST http://127.0.0.1:13302/append -d '{"msg":"hello from w2"}'
curl http://127.0.0.1:13200/debug
```

У центра вырастет `local_length`, а в `remotes` появятся оба чужых журнала с `pos` — указателем, до которого дошли.

## Настройки

`config.json` читается при старте, переменные окружения перекрывают его.

| ключ | дефолт | назначение |
|---|---|---|
| `API_PORT` | `80` | HTTP-порт: `/append`, `/debug` |
| `P2P_SEED` | случайный | Личность ноды. Задайте свой, чтобы сохранить её между перезапусками |
| `P2P_LOCAL_KEY` | — | Ключ своего журнала, проставляется сам |
| `P2P_ROOM` | — | Комната, 64 hex. Пусто — берётся свой локальный ключ |
| `P2P_REMOTE_KEY` | `''` | Ключи чужих журналов через запятую |
| `P2P_PORT` | `59737` | UDP-порт Hyperswarm |
| `P2P_REDIRECT` | `http://localhost:8999` | Куда уходят записи из чужих журналов |

Указатель по каждому чужому журналу лежит в `level` (`remote_pos_<ключ>`). В `config.json` его нет.

## Как это работает

**Комната.** Это топик Hyperswarm. Ноды с одинаковым идентификатором комнаты находят друг друга и обмениваются журналами. По умолчанию комната ноды равна её локальному ключу — то есть каждая нода владеет своей комнатой. Остальные берут идентификатор из `/debug` владельца.

**Список узлов.** `P2P_REMOTE_KEY` — ключи чужих журналов через запятую. Нода тянет их все и редиректит записи на `P2P_REDIRECT`. Указатель у каждого журнала свой.

**Дедупликация.** У записи есть `stamp`. Повторный `stamp` игнорируется: запись не попадает в журнал повторно и не редиректится заново.

## Эндпоинты

| метод | путь | что делает |
|---|---|---|
| `POST` | `/append` | Добавить запись. Повторный `stamp` игнорируется |
| `GET`/`POST` | `/debug` | Состояние ноды |

Поля `/debug`:

| поле | значение |
|---|---|
| `room` | Идентификатор комнаты |
| `local_length` | Длина своего журнала |
| `remotes` | Чужие журналы: `key`, `length`, `pos` |
| `local_last` | Последняя редиректнутая запись |
| `swarm_pubkey` | Ключ ноды в сети |
| `swarm_peers` | Подключённые пиры |
| `logs` | Последние 10 строк лога |
